# Часть I. Руководство пользователя

## 1. Установка

**Требования:** Python 3.9+.

```bash
pip install numpy pydicom PySide6
pip install scipy        # необязательно: нужен для измерения объёма (инструмент «Объём»)
```

**Необязательно:**

- **DCMTK** (должен быть в `PATH`) — нужен для работы с PACS (`findscu`, `movescu`) и как фолбэк для распаковки JPEG / JPEG-LS (`dcmdjpeg`, `dcmdjpls`).
- `pylibjpeg` или `python-gdcm` — для файлов с JPEG2000.

## 2. Запуск

```bash
python mri_viewer.py                 # пустое окно
python mri_viewer.py <папка_DICOM>   # сразу открыть папку
```

## 3. Интерфейс

- **Слева** — вкладки «Локально», «PACS», «3D / Анализ» и список найденных серий.
- **Справа** — одно или два окна просмотра (A и B). Активное окно подсвечено жёлтой рамкой; клик по окну делает его активным.
- **Сверху** — панель инструментов: инструменты, раскладка, пресет окна, инверсия, очистка измерений, сравнение и синхронизация.
- **Снизу** — строка состояния с сообщениями и предупреждениями.

## 4. Загрузка данных

### 4.1. Локальная папка

1. Вкладка «Локально» → **Открыть папку с DICOM…** (папка сканируется рекурсивно).
2. Файлы группируются по серии (`SeriesInstanceUID`) и отображаются в списке: `#номер модальность описание (кол-во срезов) · дата`.
3. Первая серия автоматически открывается в окне A. Другую серию открывают двойным кликом по списку (в активное окно) или кнопками **→ Окно A** / **→ Окно B**.
4. **Добавить папку (для сравнения)…** — добавляет серии к уже загруженным, не заменяя их.

Поддерживаются многокадровые файлы, MONOCHROME1 (инвертируется автоматически), RGB (переводится в яркость). Срезы сортируются по положению вдоль нормали (`ImagePositionPatient` / `ImageOrientationPatient`), при отсутствии — по `InstanceNumber`. Срезы другого размера пропускаются, о чём выводится предупреждение.

### 4.2. PACS

Вкладка «PACS». Параметры:

| Поле | Назначение | По умолчанию |
|---|---|---|
| Хост PACS / Порт PACS | адрес и порт сервера | 127.0.0.1 / 104 |
| AE PACS (called) | AE Title сервера | ORTHANC |
| Наш AE (calling) | AE Title программы | MRIVIEWER |
| Наш порт приёма | порт, на который PACS отправляет снимки | 11112 |
| Имя пациента, ID пациента, Модальность | фильтры поиска | `*`, пусто, MR |

1. **Найти (C-FIND)** — запрос исследований; результаты — в таблице.
2. Выберите строку → **Загрузить (C-MOVE)**. Файлы сохраняются в `~/dicom_cache/<StudyInstanceUID>` и открываются автоматически (в режиме сравнения добавляются к списку серий).
3. Журнал команд DCMTK отображается под таблицей.

На стороне PACS наш AE Title, адрес и порт приёма должны быть зарегистрированы как получатель C-MOVE.

## 5. Раскладки

Список «Раскладка» на панели: Аксиальный, Корональный, Сагиттальный, **MPR** (3 плоскости), **MPR + 3D**, **3D**. В режимах MPR на срезах отображается перекрестие текущей позиции.

## 6. Управление

### Мышь

| Действие | Результат |
|---|---|
| Колесо | листание срезов |
| Ctrl + колесо | масштаб (0.1×–20×) |
| ПКМ или СКМ + перетаскивание | сдвиг изображения |
| ЛКМ | действие активного инструмента |
| ПКМ при незаконченном измерении | отмена измерения |
| Двойной клик | сброс масштаба/сдвига и первого пресета окна |

### Клавиатура (фокус на срезе)

| Клавиша | Действие |
|---|---|
| ↑ / ←, ↓ / → | предыдущий / следующий срез |
| PageUp / PageDown | −10 / +10 срезов |
| 1–9 | пресет окна по номеру |
| I | инверсия |
| Delete / Backspace | удалить последнее измерение на текущем срезе |
| Esc | отменить незавершённое измерение |

## 7. Инструменты

| Инструмент | Использование |
|---|---|
| **W/L** | ЛКМ + движение: по X — ширина окна, по Y — центр |
| **✚ Курсор** | ЛКМ — установить позицию перекрестия MPR (синхронизирует остальные плоскости) |
| **Линейка** | два клика → расстояние в мм |
| **Угол** | три клика, вершина угла — второй точкой |
| **ROI** | растянуть эллипс: площадь, среднее ± СКО, min / max (в HU для КТ) |
| **Значение** | клик — значение в точке (HU для КТ) |
| **Объём** | клик по структуре — 3D-сегментация и объём в мл |

Измерения привязаны к плоскости и номеру среза и сбрасываются при загрузке новой серии в окно. Кнопка **Очистить измерения** удаляет их во всех окнах. Если в данных нет `PixelSpacing`, измерения выводятся в пикселях (px), а не в мм.

В левом нижнем углу среза показываются номер среза, W/L, масштаб и значение под курсором; при наличии калибровки рисуется масштабная линейка.

## 8. Окно яркости (W/L)

Список «Окно» содержит пресеты (их же вызывают клавиши 1–9):

- «Из DICOM» (если заданы WindowCenter/Width) и «Авто (1–99%)».
- Для КТ: Мягкие ткани, Мозг, Лёгкие, Кости, Средостение, Печень, Сосуды (КТА).
- Для остальных модальностей: «Контраст (5–95%)», «Широкое (0.1–99.9%)».

## 9. Сегментация объёма

Вкладка «3D / Анализ»:

- **Допуск сегментации** — процент от ширины окна W.
- **Показывать сегментацию** — включить/выключить красную подсветку.
- **Сбросить сегментацию** — удалить маску.

Инструмент «Объём»: по клику берётся медиана окрестности 3×3×3 как эталон; выбирается 3D-связная область со значениями «эталон ± допуск». Результат — объём в мл (при калибровке) и число вокселей. Если выводится «Точка вне допуска», увеличьте допуск. Требуется `scipy`.

## 10. 3D-визуализация

Рендеринг программный (NumPy), без GPU.

- **Вращение** — ЛКМ + перетаскивание; **масштаб** — колесо; **сброс** — двойной клик.
- Вкладка «3D / Анализ»: пресет, режим («Объём» — полупрозрачный рендеринг, «MIP» — проекция максимальной интенсивности), нижний и верхний пороги, непрозрачность.
- Пресеты для КТ: Кости, Мягкие ткани, Сосуды (КТА), Лёгкие; для МРТ: Ткани, Яркие структуры / MIP, Мягкий порог.
- Во время вращения используется быстрое разрешение (72 px), после отпускания — 144 px.

## 11. Сравнение исследований

1. Загрузите обе серии (например, текущую и прошлогоднюю МРТ), при необходимости через «Добавить папку».
2. Включите **Сравнение** — появится окно B. Выберите серию в списке и нажмите **→ Окно B**.
3. **Синхронизация** связывает листание, масштаб и сдвиг окон. Режим: «По положению (мм)» (по координатам срезов; если их нет — пропорционально) или «Пропорционально».

## 12. Ограничения и частые проблемы

| Проблема | Решение |
|---|---|
| «Не удалось декодировать пиксели» | установить DCMTK или `pylibjpeg` / `python-gdcm` |
| «Не найден findscu/movescu» | установить DCMTK и добавить в `PATH` |
| Измерения в px | в файле нет `PixelSpacing` |
| Инструмент «Объём» не работает | `pip install scipy` |
| 3D работает медленно | большой объём; используйте меньшие серии или режим MIP |

Прочее: вся серия загружается в память целиком (float32); косые срезы не пересэмплируются; измерения и сегментация не сохраняются в файл.

# Часть II. Подробное руководство и техническое описание

Ниже — развёрнутое описание того, как программа устроена внутри и что именно происходит при каждом действии. Раздел полезен и пользователю (чтобы понимать, откуда берутся числа и почему изображение выглядит так, а не иначе), и разработчику (чтобы расширять код).

## 13. Архитектура

Вся программа — один файл `mri_viewer.py`. Он логически делится на блоки:

| Блок | Что содержит | Назначение |
|---|---|---|
| Константы | `AX, COR, SAG`, `PLANE_NAMES`, `LAYOUTS`, `CT_PRESETS` | индексы плоскостей, названия, список раскладок, пресеты окна для КТ |
| Чтение DICOM | `Series`, `slice_pos`, `slice_key`, `scan_folder`, `decode_with_dcmtk`, `read_pixels`, `load_volume` | поиск файлов, группировка в серии, чтение пикселей, сборка объёма |
| Объём | `Volume`, `make_presets` | 3D-массив + геометрия, процентили, пресеты окна |
| Измерения | `Measure`, `measure_text`, `draw_text` | расчёт и подпись измерений |
| 2D-вид | `SliceView` | отрисовка одного среза, мышь и клавиатура |
| 3D-вид | `Volume3D` | программный рейкастинг (NumPy) |
| Панель | `Panel` | один «набор видов» (окно A или B): объём, позиция, окно W/L, измерения |
| Главное окно | `MainWindow` | панель инструментов, вкладки, список серий, синхронизация, PACS |
| Точка входа | `main()` | запуск приложения, открытие папки из аргумента |

### Иерархия объектов

- `MainWindow` владеет двумя `Panel` (`pA`, `pB`). Панель B по умолчанию скрыта и включается кнопкой «Сравнение».
- Каждая `Panel` владеет тремя `SliceView` (аксиальный, корональный, сагиттальный) и одним `Volume3D`. Раскладка лишь решает, какие из этих четырёх виджетов показаны.
- `Panel` хранит всё состояние просмотра: объём (`vol`), позицию курсора `pos = [z, y, x]`, центр и ширину окна (`wc`, `ww`), флаг инверсии, текущий инструмент, словарь измерений.

### Сигналы между компонентами

| Сигнал | Кто отправляет | Что происходит |
|---|---|---|
| `activated(panel)` | клик по виду | `MainWindow.set_active` — панель становится активной, панель инструментов перечитывает её состояние |
| `changed` | смена пресета, инверсия, загрузка объёма | обновить список пресетов и флажок «Инверсия» |
| `sliceChanged` | изменился индекс `z` | синхронизация срезов между окнами A и B |
| `viewChanged(plane)` | zoom/pan | синхронизация масштаба и сдвига |
| `status(str)` | сегментация | сообщение в строке состояния (8 с) |
| `paramsChanged` | `Volume3D.apply_preset` | обновить ползунки 3D |

## 14. Модель данных

### Series

`Series` — лёгкое описание серии, без пикселей: `uid`, `patient`, `desc`, `number`, `modality`, `date` и список `items = [(путь_к_файлу, индекс_кадра), …]`, уже отсортированный по положению среза. Метод `label()` формирует строку списка серий; дата `YYYYMMDD` преобразуется в `ДД.ММ.ГГГГ`.

### Volume

`Volume` — 3D-массив `data` формы `(Z, Y, X)`, `float32`, в реальных единицах (для КТ — HU). Поля:

| Поле | Смысл |
|---|---|
| `sz, sy, sx` | шаг по осям в мм; если нет `PixelSpacing`, все равны 1.0 |
| `calibrated` | есть ли `PixelSpacing` (определяет единицы: мм или px) |
| `z_pos` | массив положений срезов (мм) |
| `has_pos` | положения взяты из файлов (иначе построены искусственно по толщине) |
| `modality` | `CT`, `MR` и т. д. |
| `dicom_wl` | окно из DICOM (`WindowCenter`, `WindowWidth`) либо `None` |
| `mono1` | `PhotometricInterpretation == MONOCHROME1` |
| `warn` | предупреждения при загрузке |
| `mask` | булев 3D-массив сегментации либо `None` |
| `pct` | процентили 0.1, 1, 5, 95, 99, 99.9, 99.99 |
| `vmin, vmax` | минимум и максимум данных |

Процентили считаются по прореженной выборке `data[:, ::4, ::4]` — это ускоряет расчёт и почти не влияет на результат.

### Measure

`Measure(kind, pts, text)`: тип (`dist`, `angle`, `probe`, `ellipse`, `region`), точки в координатах изображения (столбец, строка) и список строк подписи. Хранятся в `Panel.meas[(плоскость, индекс_среза)]`.

## 15. Чтение DICOM

### 15.1. Сканирование папки (`scan_folder`)

1. Рекурсивный обход `Path(folder).rglob("*")`.
2. Для каждого файла — `pydicom.dcmread(..., stop_before_pixels=True, specific_tags=[…])`. Читаются только нужные теги и не читаются пиксели, поэтому сканирование быстрое.
3. Файлы, которые не удалось прочитать как DICOM, и файлы без `SeriesInstanceUID` молча пропускаются.
4. Файлы группируются по `SeriesInstanceUID`. Для новой серии запоминаются пациент, описание, номер, модальность, дата исследования.
5. Для каждого файла считается ключ сортировки (`slice_key`) и добавляются все кадры (`NumberOfFrames`).
6. Внутри серии элементы сортируются по `(ключ, кадр, путь)`, серии — по `SeriesNumber`.

### 15.2. Положение среза (`slice_pos`, `slice_key`)

Положение среза — это проекция `ImagePositionPatient` на нормаль плоскости среза. Нормаль — векторное произведение двух векторов `ImageOrientationPatient`:

`pos = IPP · (row × col)`

Если тегов нет или они некорректны, `slice_key` берёт `InstanceNumber`. Так срезы упорядочиваются корректно даже в сериях, где номера экземпляров идут «не в ту сторону».

### 15.3. Чтение пикселей (`read_pixels`)

1. Файл читается целиком; `ds.pixel_array`. Если pydicom не смог декодировать — запускается фолбэк `decode_with_dcmtk` (`dcmdjpeg`, затем `dcmdjpls`) во временной папке. Если и это не помогло — ошибка с подсказкой установить DCMTK, `pylibjpeg` или `python-gdcm`.
2. RGB (`SamplesPerPixel == 3`) переводится в яркость усреднением каналов.
3. Одиночный кадр оборачивается в массив `[1, h, w]`.
4. Применяется линейное преобразование: `значение = пиксель × RescaleSlope + RescaleIntercept` (для КТ получаются HU).
5. Из заголовка берутся: окно (`WindowCenter`/`WindowWidth`, первое значение, если их несколько), `PixelSpacing` (или `ImagerPixelSpacing`), толщина (`SpacingBetweenSlices`, иначе `SliceThickness`), положение среза, модальность, признак MONOCHROME1.

### 15.4. Сборка объёма (`load_volume`)

1. Файлы читаются по порядку; многокадровый файл читается один раз (повторное чтение кэшируется по пути).
2. Форма первого среза считается эталонной; срезы другой формы пропускаются и считаются (`skipped`).
3. Если нет ни одного пригодного среза — исключение «В серии нет пригодных срезов».
4. Срезы складываются `np.stack` в `float32`.
5. **Шаг по Z (`dz`):** если у всех срезов есть положение (и срезов больше одного), берётся медиана модулей разностей соседних положений. Если она меньше 0.001 мм (дубли положений) или положений нет, используется толщина среза (по умолчанию 1.0), а `has_pos` становится `False`.
6. Для многокадровых файлов положения отдельных кадров не определяются, поэтому `has_pos = False`.
7. Формируются предупреждения: «Пропущено срезов другого размера: N» и «Нет PixelSpacing — измерения в пикселях».

> Загрузку можно отменить кнопкой «Отмена» в окне прогресса — в этом случае объём не создаётся и текущая панель остаётся без изменений.

## 16. Системы координат и ориентация

Массив `data` индексируется `[z, y, x]`. Три плоскости получаются сечениями:

| Плоскость | Сечение | Форма | Шаги (строка, столбец) |
|---|---|---|---|
| Аксиальная | `data[z]` | Y × X | `(sy, sx)` |
| Корональная | `data[::-1, y, :]` | Z × X | `(sz, sx)` |
| Сагиттальная | `data[::-1, :, x]` | Z × Y | `(sz, sy)` |

Инверсия оси Z в двух последних сечениях (`::-1`) нужна, чтобы голова оказывалась **вверху** изображения. Предполагается, что срезы упорядочены по возрастанию положения, а ось Z направлена к голове; если в исследовании это не так, вертикальное направление корональных и сагиттальных срезов будет зеркальным.

Перевод клика в индексы объёма (`Panel.set_cursor_from`): аксиальная — `y = строка, x = столбец`; корональная — `z = Z − 1 − строка, x = столбец`; сагиттальная — `z = Z − 1 − строка, y = столбец`. Положение перекрестия (`cross_uv`) считается обратным преобразованием со сдвигом на 0.5 пикселя, чтобы линии проходили через центр пикселя.

Изображение вписывается в окно с учётом физических размеров: масштаб `fit = min(ширина_окна / ширина_мм, высота_окна / высота_мм) × zoom` (пикселей экрана на мм). Поэтому пиксели с неквадратным шагом и корональные/сагиттальные срезы с другим шагом по Z отображаются в правильных пропорциях.

## 17. Окно яркости и пресеты

### 17.1. Формула окна

Для центра `wc` и ширины `ww`: нижняя граница `lo = wc − ww / 2`; яркость пикселя `= clip((значение − lo) / ww, 0, 1) × 255`. Всё, что ниже `lo`, — чёрное, выше `lo + ww` — белое.

### 17.2. Инверсия

Изображение инвертируется (`255 − яркость`), если `mono1 != invert`. То есть MONOCHROME1 по умолчанию показывается корректно (инвертированным), а кнопка «Инверсия» и клавиша `I` переворачивают текущую картинку.

### 17.3. Как формируются пресеты (`make_presets`)

- «Из DICOM» — только если в файле заданы `WindowCenter` и `WindowWidth`.
- «Авто (1–99%)» — центр между 1-м и 99-м процентилями, ширина — их разность (не меньше 1).
- Для КТ добавляются фиксированные пресеты (центр, ширина, HU):

| Пресет | Центр | Ширина |
|---|---|---|
| Мягкие ткани | 40 | 400 |
| Мозг | 40 | 80 |
| Лёгкие | −600 | 1500 |
| Кости | 400 | 1800 |
| Средостение | 50 | 350 |
| Печень | 60 | 160 |
| Сосуды (КТА) | 300 | 700 |

- Для остальных модальностей (МРТ и др.) — «Контраст (5–95%)» и «Широкое (0.1–99.9%)».

Порядок пресетов совпадает с нумерацией горячих клавиш 1–9. Например, для КТ с окном в DICOM клавиша 1 — «Из DICOM», 2 — «Авто», 3 — «Мягкие ткани» и т. д.; если окна в DICOM нет, все номера сдвигаются на единицу вверх. Пресет с номером 1 (индекс 0) также применяется двойным кликом.

### 17.4. Ручная подстройка (инструмент W/L)

При перетаскивании ЛКМ: `шаг = max(ww / 400, 0.05)`; центр меняется на `Δy × шаг`, ширина — на `Δx × шаг` (минимум 1). Чем шире окно, тем крупнее шаг, поэтому управление остаётся удобным и для узких окон мозга, и для широких костных.

## 18. Отрисовка среза (`SliceView`)

Порядок действий при каждой перерисовке:

1. `render()` берёт сечение объёма для текущего индекса, применяет окно (раздел 17), инверсию и, если включена сегментация, подмешивает красный цвет к пикселям маски: `цвет = 0.55 × яркость + 0.45 × (255, 40, 40)`. Результат превращается в `QImage` (градации серого или RGB).
2. `paintEvent` рисует изображение с плавной интерполяцией в прямоугольник, рассчитанный `_geom()` (с учётом zoom и сдвига).
3. В режимах MPR поверх рисуется перекрестие — две полупрозрачные жёлтые линии через текущую позицию.
4. Поверх рисуются сохранённые измерения текущего среза (голубой цвет) и незавершённое измерение («черновик»). Для линейки и угла к черновику добавляется точка под курсором, поэтому линия тянется за мышью, а значение обновляется «вживую».
5. Рисуются подписи в углах (текст имеет тёмную тень, чтобы читаться на любом фоне):
   - верх слева: название плоскости и заголовок серии (`пациент | серия`);
   - низ слева: номер среза `n/N`, значения `W`, `L`, `zoom`, а под курсором — координаты пикселя `x, y` и значение (HU для КТ);
   - низ справа: масштабная линейка (если есть калибровка).

**Масштабная линейка.** Длина 100 экранных пикселей переводится в мм (`100 / fit`), затем выбирается наибольшее «круглое» значение из `1, 2, 5, 10, 20, 50, 100, 200` мм, не превышающее его. Линия рисуется длиной `значение × fit` пикселей.

Активный инструмент определяется панелью, поэтому при переключении инструмента он меняется сразу во всех видах и обоих окнах; незавершённые измерения при этом отбрасываются.

## 19. Измерения: формулы и поведение

Все измерения задаются в координатах изображения «столбец, строка» и переводятся в миллиметры умножением на шаги `sx` (по столбцам) и `sy` (по строкам) соответствующей плоскости. Единицы — мм при наличии калибровки, иначе px.

| Инструмент | Как создаётся | Формула / результат |
|---|---|---|
| Линейка | 2 клика | `√((Δx·sx)² + (Δy·sy)²)` |
| Угол | 3 клика; вершина — 2-я точка | угол между векторами вершина→точка 1 и вершина→точка 3: `arccos(v1·v2 / (\|v1\|·\|v2\|))`, в градусах; при нулевой длине — 0° |
| Значение | 1 клик | значение пикселя (координаты ограничиваются границами изображения); для КТ с подписью HU, иначе с одним знаком после запятой |
| ROI (эллипс) | перетаскивание ЛКМ | площадь `π·a·sx·b·sy` (a и b — полуоси в пикселях), среднее ± стандартное отклонение, минимум и максимум по пикселям внутри эллипса |
| Объём | 1 клик | объём в мл и число вокселей (см. раздел 20) |

Подробности:

- **ROI.** Пиксель входит в эллипс, если его центр (с поправкой +0.5) удовлетворяет уравнению `((x − cx)/a)² + ((y − cy)/b)² ≤ 1`. Если полуось меньше 0.5 пикселя, статистика не считается. Слишком маленький эллипс (менее 3 экранных пикселей по ширине) при отпускании кнопки не сохраняется.
- **Привязка к срезу.** Измерение сохраняется для пары «плоскость + индекс среза» и показывается только на этом срезе. Измерение, сделанное на аксиальном срезе 20, не появится на других срезах и в других плоскостях.
- **Удаление.** `Delete` или `Backspace` удаляет последнее измерение текущего среза в активном виде; «Очистить измерения» в панели инструментов удаляет все измерения в обоих окнах; `Esc` и ПКМ отменяют незавершённое.
- **Точность.** Для КТ значения в HU корректны при наличии `RescaleSlope`/`RescaleIntercept`. Для МРТ значения безразмерны и зависят от протокола, поэтому сравнивать их между разными сериями нельзя.
- **Ограничения.** Измерения плоские (в плоскости среза); расстояния и площади не учитывают наклон срезов относительно осей.

## 20. Сегментация и объём (`Panel.region_grow`)

Алгоритм — выращивание области по связности:

1. Клик по структуре определяет воксель-семя `(z, y, x)` (для корональной и сагиттальной плоскостей используется то же преобразование индексов, что и для перекрестия).
2. Эталонное значение `ref` — медиана куба 3×3×3 вокруг семени (устойчиво к шуму).
3. Допуск `tol = ww × доля / 100`, где `ww` — текущая ширина окна, доля — значение поля «Допуск сегментации» (1–100 %, по умолчанию 15).
4. Строится булева маска всех вокселей объёма со значением в `[ref − tol, ref + tol]`.
5. `scipy.ndimage.label` разбивает маску на связные компоненты (связность по граням, 6 соседей), выбирается компонента, содержащая семя.
6. Она сохраняется в `vol.mask` и подсвечивается красным на всех срезах; считается число вокселей `cnt`.
7. Объём: `V = cnt × sz × sy × sx / 1000` мл (если есть калибровка), иначе — только число вокселей. Результат пишется на изображение и в строку состояния.

Важно знать:

- Допуск зависит от **ширины окна**: перед сегментацией выставьте окно, в котором структура хорошо видна.
- Хранится **одна** маска на объём — новый клик заменяет предыдущую.
- Если семя не попадает в допуск, выводится «Точка вне допуска — увеличьте допуск». Если область «протекает» в соседние ткани, допуск нужно уменьшить.
- Метод не учитывает форму и не является точной сегментацией органов: объём приблизителен и сильно зависит от допуска и контраста.
- Без `scipy` инструмент показывает предупреждение с командой установки.
- Операция строит несколько вспомогательных массивов размером с весь объём, поэтому на больших сериях требует заметного объёма памяти и времени (показывается курсор ожидания).

## 21. 3D-рендеринг (`Volume3D`)

Используется программный рейкастинг на NumPy (без видеокарты). Последовательность вычислений:

1. **Сетка лучей.** Строится куб `N × N × N` точек выборки (`N = 72` при вращении и `144` в покое). Размер куба в мм: `L = max(размеры объёма) × 1.15 / zoom`.
2. **Поворот.** Матрица `Rz(azimuth) · Rx(elevation) · B`, где `B` задаёт оси экрана (вправо, вниз, вглубь). Начальные углы: азимут 25°, подъём 15°.
3. **Выборка.** Каждая точка переводится в координаты объёма (в мм), затем в индексы вокселей (ближайший сосед). Точки вне объёма получают минимальное значение.
4. **Передаточная функция.** Диапазон `[0.1%, 99.99%]` процентилей данных нормируется в `0…1`. Пороги «Нижний» и «Верхний» задают долю этого диапазона; значение отображается в `t ∈ [0, 1]`.
5. **Режим MIP.** Берётся максимум `t` вдоль луча — получается проекция максимальной интенсивности (в градациях серого).
6. **Режим «Объём».** Непрозрачность вокселя `a = clip(t^1.5 × opacity, 0, 0.98)`; вдоль луча накапливается пропускание (`cumprod(1 − a)`), вклад вокселя — `пропускание_до × a × (0.35 + 0.65·t) × затухание_по_глубине`; затем окрашивание тёплым оттенком `(1.0, 0.93, 0.82)`.
7. Результат — квадратное изображение `N × N`, растягиваемое на меньшую сторону виджета.

Управление: перетаскивание ЛКМ — вращение (0.6° на пиксель, подъём ограничен ±90°), колесо — масштаб (0.3×–4×), двойной клик — сброс.

**Пресеты КТ** (заданы в HU, пересчитываются в доли диапазона): «Кости» 250…1800, непрозрачность 0.6 (открывается по умолчанию); «Мягкие ткани» −100…300, 0.3; «Сосуды (КТА)» 150…600, 0.5; «Лёгкие» −900…−400, 0.3.

**Пресеты не-КТ:** «Ткани» (0.25…1.0, 0.35), «Яркие структуры / MIP» (0.5…1.0, MIP), «Мягкий порог» (0.12…1.0, 0.25).

Особенности: 3D-вид не использует окно W/L и маску сегментации; интерполяция «ближайший сосед» даёт заметную «ступенчатость» на сериях с толстыми срезами; на больших объёмах расчёт ощутимо медленнее, поэтому при вращении используется пониженное разрешение.

## 22. Главное окно и синхронизация

### 22.1. Активное окно

Панель инструментов управляет **активной** панелью: список пресетов, флажок инверсии и ползунки 3D показывают её состояние. Смена активной панели (клик по окну) перечитывает эти элементы. Выбор инструмента и раскладки применяется ко всем окнам сразу.

### 22.2. Синхронизация срезов

Работает, если включены «Синхронизация» и окно B. Срабатывает при смене аксиального индекса `z` в одном из окон:

- «По положению (мм)» — в другом окне выбирается срез с ближайшим значением `z_pos` (нужно, чтобы в обоих объёмах были реальные положения срезов);
- «Пропорционально» (или когда положений нет) — относительное положение `i / (N − 1)` переносится на другой объём.

Режим «по положению» осмыслен только если исследования привязаны к одной системе координат пациента; для двух разных исследований (например, за разные годы) надёжнее «Пропорционально» либо ручная подстройка. Перемещение курсора по осям `x`/`y` в окнах не синхронизируется.

### 22.3. Синхронизация вида

Масштаб и сдвиг плоскости копируются в одноимённый вид другого окна. Окно яркости и инверсия у окон независимы.

## 23. PACS: что именно выполняется

Программа не реализует протокол DICOM самостоятельно, а запускает утилиты DCMTK через `QProcess` (интерфейс не блокируется, вывод идёт в журнал). Одновременно допустима только одна операция — иначе появится сообщение «Предыдущая операция ещё идёт».

**Поиск (C-FIND)** — `findscu` со следующими параметрами: режим Study Root (`-S`), AE-титулы (`-aet` наш, `-aec` сервера), ключи `QueryRetrieveLevel=STUDY`, `PatientName`, `PatientID`, `StudyDate`, `StudyDescription`, `ModalitiesInStudy`, `StudyInstanceUID`; ответы сохраняются в файлы `rsp*.dcm` во временной папке (`-X -od`) и разбираются в таблицу. Пустые поля «ID пациента» и «Модальность» запрашиваются без фильтра.

**Загрузка (C-MOVE)** — `movescu` с теми же AE-титулами, адресатом `-aem` (наш AE) и портом приёма `+P`; уровень STUDY, ключ `StudyInstanceUID` выбранной строки. Файлы сохраняются в `~/dicom_cache/<StudyInstanceUID>`. После успешного завершения (код 0) папка сканируется автоматически.

Замечания по безопасности и эксплуатации:

- Кэш `~/dicom_cache` содержит персональные данные пациентов и сам не очищается — удаляйте его по окончании работы в соответствии с политикой вашей организации.
- Соединение DICOM по умолчанию не шифруется; для передачи по незащищённым сетям используйте VPN или защищённый канал.
- Для C-MOVE сервер должен знать наш AE Title и адрес/порт приёма — иначе загрузка завершится ошибкой, хотя поиск будет работать.

## 24. Типовые сценарии работы

### 24.1. Быстрый просмотр исследования

1. Запустите `python mri_viewer.py <папка>` или откройте папку кнопкой.
2. Выберите раскладку **MPR + 3D**.
3. Листайте колесом в аксиальном виде; при необходимости подберите окно клавишами 1–9.
4. Включите **✚ Курсор** и кликните по интересующей точке — все три плоскости перейдут к ней.

### 24.2. Измерение размера образования

1. Найдите срез, где образование максимально.
2. Подберите окно, в котором границы видны чётче всего.
3. Выберите **Линейка**, поставьте две точки на границах — получите размер в мм.
4. Для площади и плотности выберите **ROI** и растяните эллипс по образованию — получите S, среднее ± СКО, min/max.
5. Повторите измерение в другой плоскости, чтобы проверить размер по трём осям.

### 24.3. Оценка объёма структуры

1. Подберите окно, где структура контрастна.
2. Во вкладке «3D / Анализ» задайте допуск (начните с 10–15 %).
3. Выберите **Объём** и кликните внутри структуры.
4. Проверьте красную маску на разных срезах. Если маска «вытекла», уменьшите допуск; если слишком мала — увеличьте.
5. Для нового расчёта нажмите «Сбросить сегментацию» либо просто кликните заново.

### 24.4. Сравнение с предыдущим исследованием

1. Откройте папку с текущим исследованием.
2. Во вкладке «Локально» нажмите «Добавить папку (для сравнения)…» и выберите прошлогоднее.
3. Выберите серию в списке, нажмите **→ Окно B (сравнение)** — окно включится само.
4. В окне A откройте соответствующую серию текущего исследования (двойной клик).
5. Включите «Синхронизацию». Если срезы не совпали, переключите режим на «Пропорционально».

### 24.5. Работа с PACS

1. Вкладка «PACS»: заполните хост, порты и AE-титулы.
2. «Найти (C-FIND)» → дождитесь строк в таблице.
3. Выберите исследование → «Загрузить (C-MOVE)».
4. По окончании серии появятся в списке и первая откроется в окне A.

## 25. Сообщения программы и что они означают

| Сообщение | Причина | Что делать |
|---|---|---|
| «DICOM-файлы не найдены» | в папке нет читаемых DICOM или у них нет `SeriesInstanceUID` | проверьте папку; убедитесь, что это DICOM-файлы |
| «В серии нет пригодных срезов» | все срезы не прочитаны или несовместимы | проверьте целостность файлов |
| «Ошибка: …» при открытии серии | проблема чтения/декодирования | см. текст; чаще всего нужен DCMTK или `pylibjpeg` |
| «Не удалось декодировать пиксели…» | сжатый формат, который не поддерживает установленный декодер | установить DCMTK, `pylibjpeg` или `python-gdcm` |
| «Пропущено срезов другого размера: N» | в серии срезы разных размеров | серия может быть смешанной (например, локалайзеры) — проверьте исходные данные |
| «Нет PixelSpacing — измерения в пикселях» | нет калибровки | измерения в мм и объёмы в мл недоступны |
| «Для измерения объёма нужен scipy» | не установлен `scipy` | `pip install scipy` |
| «Точка вне допуска — увеличьте допуск» | значение в точке не вошло в диапазон | увеличьте допуск или выберите другую точку |
| «Не найден «findscu»/«movescu»» | DCMTK не установлен или не в `PATH` | установить DCMTK, перезапустить программу |
| «Предыдущая операция ещё идёт» | уже выполняется C-FIND/C-MOVE | дождаться завершения |
| «Выберите исследование в таблице» | не выбрана строка перед загрузкой | выбрать строку |

## 26. Производительность и память

- **Память.** Вся серия хранится в `float32` — 4 байта на воксель. Например, 512 × 512 × 300 ≈ 315 МБ. Сегментация дополнительно создаёт маски (в том числе целочисленную карту меток), то есть может временно потребовать ещё несколько сотен МБ.
- **Загрузка.** Время определяется числом файлов и их сжатием. Сжатые JPEG-файлы, требующие DCMTK, загружаются заметно медленнее (каждый файл распаковывается внешней утилитой).
- **3D.** Работает на процессоре. Разрешение 144 × 144 (при выборке `N³` ≈ 3 млн точек) в покое и 72 × 72 при вращении. На слабых машинах уменьшите объём (используйте серии с меньшим числом срезов) или режим MIP.
- **Интерфейс.** Окно прогресса при загрузке обновляется каждый срез; нажатие «Отмена» прерывает загрузку.

## 27. Известные ограничения

- Объём не пересэмплируется: предполагаются срезы, перпендикулярные оси Z. Наклонные (косые) срезы отображаются в «сырой» геометрии.
- Для неравномерных расстояний между срезами используется медианный шаг — вертикальный масштаб корональных/сагиттальных видов может быть неточным.
- Измерения не сохраняются в файл и пропадают при загрузке новой серии в окно; экспорт и отчёты не реализованы.
- Нет поддержки DICOM-SR/SEG, аннотаций, нескольких фаз/временных рядов (динамические серии не разделяются) и цветных карт.
- В 3D не используется окно яркости и сегментация; интерполяция — «ближайший сосед».
- Многокадровые файлы загружаются, но положения отдельных кадров не учитываются (режим «по положению» недоступен).
- Для файлов без стандартного заголовка DICOM (без префикса `DICM`) чтение при сканировании пропускается.
- Программа предназначена для просмотра и справочных измерений; использование в клинической практике для диагностики требует отдельной валидации и сертификации.

## 28. Расширение программы

### Добавить пресет окна для КТ

Добавьте пару в `CT_PRESETS`: `("Название", (центр, ширина))`. Он автоматически появится в списке и получит горячую клавишу, если его номер не больше 9.

### Добавить раскладку

1. Добавьте название в `LAYOUTS`.
2. В `Panel.set_layout` добавьте ветку, расставляющую виджеты в сетке (`add(виджет, строка, столбец, [занимаемых строк, столбцов])`).
3. Если раскладка показывает перекрестие, добавьте её в условие для флага `multi`.

### Добавить инструмент измерения

1. Добавьте кортеж `(ключ, название, подсказка)` в список `tools` в `MainWindow._build_toolbar`.
2. В `measure_text` добавьте расчёт текста для нового типа (возвращает список строк).
3. В `SliceView.mousePressEvent` опишите, как собираются точки (по образцу `dist`/`angle`).
4. В `SliceView._draw_measure` добавьте отрисовку фигуры.

### Сменить параметры 3D

Разрешения `fast` и `hq` заданы в конструкторе `Volume3D` (по умолчанию 72 и 144). Начальные углы, прозрачность и пресеты — в `Volume3D.__init__` и `set_volume`.

## 29. Глоссарий

| Термин | Значение |
|---|---|
| DICOM | стандарт хранения и передачи медицинских изображений |
| PACS | архив и сервер медицинских изображений |
| AE Title | имя приложения-участника обмена DICOM |
| C-FIND / C-MOVE | запрос списка исследований / запрос на пересылку изображений |
| MPR | мультипланарная реконструкция: срезы в трёх взаимно перпендикулярных плоскостях |
| MIP | проекция максимальной интенсивности |
| W/L (Window/Level) | ширина и центр окна яркости |
| HU | единицы Хаунсфилда — шкала плотности в КТ |
| ROI | область интереса |
| Воксель | элемент объёма (3D-пиксель) |
| PixelSpacing | физический размер пикселя (мм) |
| Аксиальная / корональная / сагиттальная | поперечная / фронтальная / боковая плоскость сечения |
